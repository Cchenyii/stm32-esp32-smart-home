此页保留 P0 最小心跳工程的历史记录。当前 STM32 应用已改用 FreeRTOS，调试观察量为 `edge_diagnostics`。实际接线与运行步骤见 [上板配置与验收](上板配置与验收.md)。

- STM32CubeMX 6.18.1，已缓存 STM32CubeF4 V1.28.3。
- STM32CubeIDE 2.2.0，内置 Arm GCC 14.3.1、GDB 和 STM32CubeProgrammer 2.23.0。
- ESP-IDF v6.1 位于 `C:\esp\v6.1\esp-idf`。`idf.py --version` 返回 v6.1，Python 依赖检查通过。ESP32 的 Xtensa GCC 15.2.0 可以运行。P0 选用已有的 v6.1。
- PC 侧已有 Python 3.12.9、Git 2.55.0.windows.5 和 VS Code 1.139.1。

## P0 顺序

1. **STM32 编译，已通过。** CubeMX 按 STM32F407VET6 生成 CubeIDE 工程，系统时钟使用内部 16 MHz HSI，HAL 使用 SysTick 时基。2026-11-19 的 Debug 全量构建为 0 错误、0 警告，产物是 `STM32/Debug/STM32.elf`。
2. **STM32 下载与运行。** 将 ST-Link 接到电脑，确认能列出探针。按开发板的实物丝印或原理图核对供电和 SWD 排针，再连接目标板。下载时记录写入校验和目标电压。运行后暂停两次，确认计数增加。复位停在 `main` 时检查计数回到零。
3. **ESP32 编译、下载与运行。** 用现有 ESP-IDF v6.1 选择 `esp32` 目标，编译最小日志工程。接入主链路使用的 ESP32 后，以插拔前后的 COM 口变化确认设备，烧录并记录串口启动日志。
4. **记录板级信息。** 结合板号、丝印和实测结果确定传感器供电与候选引脚，记录尚待验证的电平和地址。STM32 和 ESP32 均完成实际启动验收、P1 所需的接线条件明确后，再进入驱动开发。

## STM32 工程及调试

- `STM32/STM32.ioc` 管理芯片、时钟和外设配置。
- `STM32/Core/Src/main.c` 的 `USER CODE` 区包含计数器和循环。启动代码清零静态存储的计数器，`HAL_Init()` 初始化 HAL 时基。主循环通过 `HAL_Delay(500U)` 等待 SysTick 推进，再递增计数。`volatile` 使每次写入可供调试器观察。
- 在 STM32CubeIDE 中用 **File → Import → General → Existing Projects into Workspace** 导入 `STM32`，选择 Debug 配置，执行 **Project → Build Project**。调试连接选择 SWD。将 `p0_heartbeat` 加入 Expressions，Resume 几秒后 Suspend，记下数值，再重复一次。
- 若电脑识别探针但读不到芯片，先查目标板是否上电、GND 和 SWD 信号是否对应。若能进 `main` 但计数停住，可暂停查看是否进入 `Error_Handler`，或者检查 HAL 的 `uwTick` 是否在运行时增加。

### 复现命令行构建

在项目根目录打开 PowerShell，运行以下命令。编译器路径通过 CubeIDE 的 `-E` 参数传给这次构建。Debug 和 Release 的链接脚本设置已使用相对路径，在当前含中文的项目目录验证了 Debug 构建。

```powershell
$ide = 'C:\ST\STM32CubeIDE_2.2.0\STM32CubeIDE'
$gcc = rg --files $ide -g 'arm-none-eabi-gcc.exe' | Select-Object -First 1
$make = rg --files $ide -g 'make.exe' | Select-Object -First 1
$buildPath = "$(Split-Path $gcc);$(Split-Path $make);$env:Path"
$workspace = Join-Path ([IO.Path]::GetTempPath()) 'smart-iot-cubeide-build'
$project = (Resolve-Path -LiteralPath '.\STM32').Path
& (Join-Path $ide 'stm32cubeidec.exe') --launcher.suppressErrors -nosplash `
    -application org.eclipse.cdt.managedbuilder.core.headlessbuild `
    -data $workspace -import $project -cleanBuild 'STM32/Debug' -E "PATH=$buildPath"
```

## 硬件核对项

- STM32F407VET6 是已知芯片型号。上板前核对开发板板号、供电方式、SWD 排针标注和 ST-Link 排针标注。
- ESP32-WROOM-32E 是已知模组型号。主板的 USB 转串口芯片和实际 COM 口以连接结果为准。
- DHT22 核对裸件或模块、引脚顺序与上拉。HC-SR04 核对供电与 Echo 电平，再确定输入电路。4 针 I²C OLED 核对供电、引脚顺序、控制器和地址。

## 面试自查

- **为什么用 HSI？** P0 需要一套可以跨同芯片开发板复用的启动配置。HSI 由芯片内部提供，工程无需使用板上的外部晶振。
- **烧录校验通过如何证明程序在执行？** 烧录校验确认 Flash 内容。运行中两次暂停看到计数增加，再复位确认计数清零，能检查入口、主循环和 HAL 时基。
- **为什么暂时用 `HAL_Delay`？** P0 只有一个裸机循环，忙等便于用最少代码验证时基。后续的 RTOS 周期任务需要用任务延时让出 CPU。
