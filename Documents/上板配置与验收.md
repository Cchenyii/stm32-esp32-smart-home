# 上板配置与验收

## 智能家居本地版

使用 `EDGE_HOME_PROFILE` 编译，启用[智能家居板级配置](../STM32/Core/Inc/edge_board_home.h)。实测使用 PS2 摇杆，需同时定义 `EDGE_HOME_JOYSTICK`。使用 GPIO25 → PD6 的实测串口接线时，再定义 `EDGE_HOME_UART_RX_PD6`。[STM32F407 数据手册](https://www.st.com/resource/en/datasheet/stm32f407ve.pdf)

- DHT22 以 3.3 V 供电，`DATA` 接 `PC0`。OLED 以 3.3 V 供电，`SCL` 接 `PB8`、`SDA` 接 `PB9`，固件探测地址 `0x3C` 和 `0x3D`。
- 智能家居版使用 SSD1306 反相命令 `0xA7`，白光屏呈现白底黑字。首页为大号温度、湿度、相对光照进度条、模式和设备指令。右上角实心标记表示 ESP32 串口心跳在线，空心表示链路离线。
- 光照模块以 3.3 V 供电，`AO` 接 `PA5/ADC1_IN5`，`DO` 留空。此前版本使用 `PA1`，该脚在与照片匹配的 DevEBox 板图上与板载 LED 共用。改接 `PA5` 需配套烧录采用该引脚的固件。[开发板原理图](https://stm32-base.org/assets/pdf/boards/original-schematic-STM32F407VGT6_STM32F4XX_M.pdf) 用手遮挡和照亮模块，对照 SWD 的 `edge_last_light.raw`。若光越强原始值越小，将板级配置的 `light_decreases_with_brightness` 设为 `true`。浮空的 ADC 仍可能返回数值，接好 AO 再验收自动窗帘。
- **JY-25-003 风扇套装**。驱动板 `VCC` 接适配器 5 V，`GND` 接共地，`GPIO` 接 STM32 `PC4`。套装风扇的白色 2P 插头接驱动板输出座。按商品图采用低电平开启和 3.3 V 高电平关闭，固件初始化和故障停机写关闭电平。首测确认实物在 5 V 供电时接受 3.3 V 控制。先启动 STM32，再接通执行器的 5 V。
- SG90 的 PWM 信号接 `PB6/TIM4_CH1`，电源用同一外部 5 V 并共地。初始脉宽设为开 1100 µs、关 1900 µs，周期 20 ms。先空载确认方向和行程，再接窗帘机构。
- 按键 `MODE`、`UP`、`DOWN` 分别接 `PC1`、`PC2`、`PC3`。默认按下为低电平，启用内部上拉。若买到按下为高电平的 3.3 V 按键模块，将 `keys_active_high` 设为 `true`。简单常开开关只需接对应 GPIO 和 GND。
- 五针 PS2 摇杆可以替换三个按键。摇杆电源脚（可能印 `+5V`）接 `3V3`，`GND` 接公共地，`SW` 接 `PC1`，`VRy` 接 `PC2/ADC2_IN12`，`VRx` 和 `PC3` 留空。用 `EDGE_HOME_PROFILE` 与 `EDGE_HOME_JOYSTICK` 一起编译。上下拨动对应 `UP/DOWN`，按下对应 `MODE`。上电时把摇杆放回中间，拨一次后松手回中再拨。若实物上下方向相反，可将摇杆模块平面旋转 180°。
- STM32 用自己的 USB。5 V / 2 A 适配器的同尺寸圆头母座将 `+5V`、`GND` 引到面包板独立电源排，给风扇驱动板与舵机供电。适配器负极接 STM32 `GND`，正极只接执行器。传感器、显示屏和按键从 STM32 `3V3` 取电。接线在断电时完成。

上电为 AUTO，风扇关闭，舵机保持无脉冲，直到光照有效且越过阈值。默认温度达到 30°C 开风扇，降到 28°C 停。光照达到 3000 关帘，低于或等于 2500 开帘，舵机两次位置命令至少相隔 1.2 s。AUTO 中温度失效会停风扇，光照失效会保持舵机上次命令位置。OLED 显示的是已下发的执行状态，普通 SG90 无位置回读。

- 首页短按 `MODE` 进入 `MENU`。`UP/DOWN` 循环选择 `RUN MODE`、`FAN TEMP`、`LIGHT LIMIT` 或 `BACK HOME`，再短按 `MODE` 打开。在菜单或子页长按 `MODE` 直接回首页。
- `RUN MODE` 页用 `UP` 选 AUTO、`DOWN` 选 MANUAL，短按 `MODE` 确认后回菜单。进入 MANUAL 时保留风扇状态及上次下发的窗帘位置。回到手动模式的首页后，`UP` 切风扇，`DOWN` 切窗帘。切回 AUTO 时按当前有效读数重新计算。
- 阈值页用 `UP/DOWN` 增减温度 1°C 或相对亮度 100 个计数，修改即时生效，短按 `MODE` 回菜单。复位后恢复默认阈值。菜单开启期间自动联动照常运行，手机远程控制在回到首页约 1.2 秒后恢复。

审查顺序从 [任务和队列](../STM32/Core/Src/edge_app.c) 进入，接着看 [控制与按键状态机](../STM32/Core/Src/edge_home.c)、[ADC、PWM 和 GPIO](../STM32/Core/Src/edge_home_io.c)、[DHT22 驱动](../STM32/Core/Src/edge_board.c) 及 [OLED 首页和菜单](../STM32/Core/Src/edge_oled_ui.c)。断点或观察窗口中可查看 `edge_last_sample`、`edge_last_light`、`edge_home_view` 和 `edge_oled_address`。

## ThingsBoard Cloud 接入

1. 按[实测 UART 接线](#智能家居联网)连接一块 ESP32。STM32 和 ESP32 分别供电并共地。
2. 登录 ThingsBoard Cloud，在 **Entities → Devices** 创建设备，选 **Access token** 凭据。ESP32 使用设备 token 作为 MQTT 用户名，手机使用自己的平台账号。设备页的 **Check connectivity** 可核对当前区域的 MQTT 主机。默认主机为 `mqtt.thingsboard.cloud`，固件以 TLS 连接端口 8883。[平台设备接入文档](https://thingsboard.io/docs/paas/reference/mqtt-api/getting-connected/)
3. 运行 `.\Tools\Build-ESP32.ps1 -Action menuconfig`，启用 **Smart-home STM32 with MQTT** 和 **Use ThingsBoard Cloud over MQTT/TLS**。填家庭 Wi-Fi、设备地址、设备 token。UART2 的 RX 填 16，TX 按下方实际接线填 17 或 25。TLS 首次连接前会通过 NTP 校时。保存后运行 `.\Tools\Build-ESP32.ps1` 生成带实际配置的 ESP32 固件。
4. 在 **Widget Library** 导入[控制小部件](../ThingsBoard/home-control-widget.json)，再在 **Dashboards** 导入[仪表盘](../ThingsBoard/home-control-dashboard.json)。模板查找名为 `home-01` 的设备。若设备名称不同，在仪表盘编辑模式打开 **Entity aliases**，将过滤条件改为你的设备名。也可以新建 **Control widget**，使用 [HTML](../ThingsBoard/home-control.html)、[CSS](../ThingsBoard/home-control.css) 和 [JavaScript](../ThingsBoard/home-control.js) 手动配置。[ThingsBoard 自定义控制小部件](https://thingsboard.io/docs/paas/user-guide/contribution/widgets-development/rpc-control/)
5. 等待面板出现 STM32 最新快照，再切到手动模式分别测试风扇与窗帘。面板用即时双向 RPC。控制回执有拒绝、已下发以及等待舵机动作间隔几种情况。手机关闭 Wi-Fi，切到移动数据再次登录私有 Dashboard，验收异地通路。正常使用时家庭电脑可以关机，路由器、STM32 和 ESP32 需要继续供电。

云端刷新与控制入口见 [ThingsBoard 协议](通信协议.md#thingsboard-cloud)。设备掉线时小部件显示离线，历史图表可保留已上报记录。

Windows 构建脚本把生成文件放到 `ESP32/build-artifacts/`，可按该目录中的 `flash_args` 和 `flasher_args.json` 烧录。在已激活 ESP-IDF 的终端中直接构建时，从仓库根目录运行 `idf.py -C ESP32 build`，再用 `idf.py -C ESP32 -p <串口> flash monitor` 烧录并观察日志。

## 智能家居联网

本地控制验收后，再接一块 ESP32。ESP32 使用自己的 USB 供电，整机实测接线如下。

| 信号 | 连接 |
| --- | --- |
| 上报 | STM32 `PA2/TX` → ESP32 `GPIO16/RX` |
| 下行 | ESP32 `GPIO25/TX` → STM32 `PD6/RX` |
| 参考地 | STM32 `GND` ↔ ESP32 `GND` |

在 STM32 预处理器中添加 `EDGE_HOME_UART_RX_PD6`，并在 ESP32 配置中将 UART2 TX 设为 25。使用 PA3 作为 STM32 接收脚时，ESP32 TX 设为 17，STM32 构建时关闭 `EDGE_HOME_UART_RX_PD6`。

在电脑运行 Mosquitto，为网关和网页创建两个账号。在一个专用目录中执行以下命令，再把配置中的监听地址换成电脑的局域网 IPv4。

```powershell
mosquitto_passwd -c home-passwords gateway
mosquitto_passwd home-passwords dashboard
```

将以下内容分别保存为同目录的 `home.conf` 和 `home.acl`。ESP32、网页与 ACL 使用同一个设备 ID，这里为 `edge-01`。

```conf
listener 1883 192.168.1.20
allow_anonymous false
password_file home-passwords
acl_file home.acl
```

```text
user gateway
topic read smarthome/edge-01/command
topic write smarthome/edge-01/state
topic write smarthome/edge-01/ack
topic write smarthome/edge-01/availability

user dashboard
topic write smarthome/edge-01/command
topic read smarthome/edge-01/state
topic read smarthome/edge-01/ack
topic read smarthome/edge-01/availability
```

在该目录运行 `mosquitto -c home.conf`。服务用于可信局域网，路由器端口转发保持关闭。

在项目根目录执行 `.\Tools\Build-ESP32.ps1 -Action menuconfig`。启用 **Smart-home STM32 with MQTT**，填 Wi-Fi、Broker 的 IPv4 和端口、`gateway` 账号密码，按实际接线设置 TX，RX 设为 16。再执行 `.\Tools\Build-ESP32.ps1`，按构建产物目录中的 `flash_args` 下载。真实配置留在本机 `ESP32/sdkconfig`。

在项目根目录打开 PowerShell 7，安装依赖并启动网页。示例 IPv4 要改成 Broker 实际地址，网页登录的用户名为 `home`。

```powershell
python -m pip install -r PC_Server/requirements-home.txt
$env:SMARTHOME_MQTT_USER = 'dashboard'
$env:SMARTHOME_MQTT_PASSWORD = Read-Host '输入 Broker 的 dashboard 密码' -MaskInput
$env:SMARTHOME_WEB_PASSWORD = Read-Host '输入网页登录密码' -MaskInput
python -m PC_Server.home_server --broker 192.168.1.20
```

本机打开 `http://127.0.0.1:8080/`。需要用手机时，给上一行加 `--bind 192.168.1.20`，手机连同一局域网并打开对应地址。网页上的开关和窗帘位置表示 STM32 已下发的指令，实际转速和行程通过实机观察。

联机顺序为先看到实时读数，再切手动测试风扇和窗帘，再切回自动。按键操作和本地阈值页会暂时优先于网页。拔掉 ESP32 或停止 Broker 后，确认网页显示离线且 STM32 的本地控制继续。恢复联网后查看实际控制状态，再发新命令。

## 原边缘监测配置

## 1. 两块板分别启动

1. 连接 ST-Link USB，确认 CubeProgrammer 枚举探针。按目标板与探针的实物标注核对电源、GND、SWDIO、SWCLK 和是否需要 NRST。确认目标电压后，通过 SWD 下载 `STM32/Debug/STM32.elf`，检查写入校验。
2. STM32 默认固件不驱动业务引脚。用 CubeIDE 在调试器观察 `edge_diagnostics`。运行 3–5 s 后暂停，记录 `tasks_alive`、`samples`、`minimum_stack_words`、`free_heap_bytes`、`watchdog`。再次运行后应看到任务时间及采样轮次增长，`fatal_code` 为 0。默认样本属于无硬件配置状态，只验证调度和任务数据流。
3. ESP32 通过 USB 接入，记录新增 COM 口和实际 Flash 容量。先用默认构建观察串口启动日志，再用本地配置构建联调版本。每块板使用独立设备编号。

## 2. 配置实际引脚和网络

将 `STM32/Core/Inc/edge_board_local.example.h` 复制成同目录的 `edge_board_local.h`。每个启用的引脚填入 `{GPIOx, GPIO_PIN_n, GPIO_AFx_xxx}`。普通 GPIO 的 AF 字段填 0。按照原理图、排针丝印与芯片复用表共同确认，字段含义如下。

- `dht` 使用可引出的 GPIO 与相应 EXTI。驱动以开漏方式释放线，按实际模块确认供电与数据线至 3.3 V 的上拉。
- `trig` 使用普通 GPIO，`echo` 使用 PB10 的 TIM2_CH3 数字复用输入，关闭内部上下拉。PB10 在 STM32F407 数据手册中标为 FT。
- `scl`、`sda` 使用 I2C1 的对应复用功能，核对总线上拉电压。当前显示驱动支持 SSD1306 128×64，`oled_address` 填实测的 7 位地址。
- `tx`、`rx` 使用 USART2 的复用功能，内部用 DMA1 Stream5 Channel4 接收。两板使用 3.3 V 串口电平、共地，TX 与对方 RX 交叉。ESP32 的 UART2 GPIO 在 ESP-IDF 配置页填写实物已确认的引脚。

完成配置后执行 STM32 **Clean Build**。当前 `.ioc` 保留 P0 时钟与芯片配置，项目其余外设由板级 C 配置和 CubeIDE 工程选项管理。如需重新生成 CubeMX 工程文件，要核对 FreeRTOS 接入、应用中断和链接配置，再重新编译。

用 `.\Tools\Build-ESP32.ps1 -Action menuconfig` 填 Wi-Fi、PC 局域网 IPv4 与端口，然后重建 ESP32。Windows PC 监听同一 IP 和端口。无连接时先比较 PC 监听地址、ESP32 拿到的 IP、路由器是否隔离客户端及 Windows 对端口的入站规则。

## 3. 当前整机接线

断开 STM32、ESP32 和 ST-Link 的 USB 再接线。接完后，STM32 和主 ESP32 分别用自己的 USB 供电，ST-Link 继续接电脑。保留 SWD 的 `CLK`、`DIO` 和 `GND`。STM32 的 `BT0` 与 `3V3` 之间留空，两个开发板之间只连串口信号和地。

- **ESP32 主板**。STM32 `PA2`（TX）→ NodeMCU-32S 的 `P16`（GPIO16 / RX），`P17`（GPIO17 / TX）→ STM32 `PA3`（RX），`GND` ↔ `GND`。
- **OLED**。商品资料标为 SSD1306、128×64、四针 I²C，支持 3.3 V。`VCC` → STM32 `3V3`，`GND` → `GND`，`SCL` → `PB8`，`SDA` → `PB9`。使用实物丝印定位，固件探测 `0x3C` 和 `0x3D`。
- **DHT22**。商品资料标明三针模块自带数据线上拉。`VCC/+` → STM32 `3V3`，`GND/-` → `GND`，`DATA/OUT/S` → `PC0`。使用实物丝印定位，不需要另接上拉电阻。
- **HC-SR04**。商品图标称 5 V，用户此前使用 3.3 V 测距成功。本次先按 3.3 V 实测。`VCC` → STM32 `3V3`，`GND` → `GND`，`TRIG` → `PA4`，`ECHO` → `PB10`。模块与 STM32 共用同一 3.3 V 电源，断电后接线。PB10 为耐 5 V 的数字输入，见 [STM32F407 数据手册](https://www.st.com/resource/en/datasheet/stm32f407ve.pdf)。
- **第二块 ESP32**。作为独立测试节点，仅通过自己的 USB 接电脑。给主板和第二块板分别做标记。

本次以 3.3 V 能否稳定采集为实测项。若频繁超时或读数不稳定，先留存日志，再按标称 5 V 和合适的电平转换方案复测。

联调配置写入本机忽略提交的 `STM32/Core/Inc/edge_board_local.h` 和 `ESP32/sdkconfig`。可通过 SWD 查看 `edge_last_sample`、`edge_oled_address` 和 `edge_diagnostics`。ESP32 在 Wi-Fi 或 PC 地址尚未填写时，仍会通过串口日志打印收到的 STM32 样本。I²C 地址应答可验证总线连通，控制器类型还需通过模块资料或实际显示确认。

## 4. 联调和故障验收

1. **真实数据**。逐一接 DHT22、HC-SR04、OLED，再接 UART。核对 OLED 与 PC 数据变化，拔掉一项传感器后确认相应读数变为无效。重新接回，观察恢复及故障清除日志。
2. **双向控制**。执行 `status edge-01`、`period edge-01 5000`。确认 PC 收到目标 STM32 的命令回执，并在后续 CSV 样本时间中看到周期变化。
3. **异常恢复**。分别断开 UART、关闭 PC 服务、断开 Wi-Fi，观察两段链路各自的离线计时及重连。恢复后核对有效样本和命令回执。串口异常注入需先断开原发送端，使用电平匹配的工具注入错误 CRC、半帧和有效帧，记录错误计数与后续帧。
4. **看门狗**。仅在测试构建中加编译宏 `EDGE_ENABLE_FAULT_INJECTION`。系统进入正常喂狗后，通过调试器将 `edge_suspend_worker` 设为 1 至 4，分别对应采集、处理、显示、UART。恢复执行，记录超时复位和 `edge_diagnostics.reset_flags` 中的 IWDG 复位标志。调试器暂停期间 IWDG 冻结，观察超时要让芯片继续运行。
5. **多设备与长测**。第二块 ESP32 用模拟节点模式和独立编号。确认两台同时在线且模拟样本在 CSV 里有标记。再分别跑 30 分钟、2 小时和 8 小时，记录数据量、掉线、复位、错误计数与任务栈余量。

每项实测记录日期、板号、固件版本、接线、执行步骤、预期、实测和日志。待执行项保留为待验收。
